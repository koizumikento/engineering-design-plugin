## 1. 仕様書の役割

仕様書は設計案の説明ではなく、満たすべき条件、根拠、境界、合否判定を結ぶベースラインである。概念検討では仮定を許容するが、仮定と承認済み要求を混在させない。

成果物の成熟度を明示する。

| 成熟度 | 目的 | 許容するもの | 禁止するもの |
|---|---|---|---|
| Concept | 方向性と主要制約の探索 | 明記した仮定、複数案 | 認証・量産可能性の断定 |
| Prototype | 動作・組立・検証 | 管理したTBD/TBR | 未記録の代替部品や寸法変更 |
| Production handoff | 製造・調達・試験への移管 | 承認済み逸脱 | 出典不明の規格値、未定義の合否 |

## 2. 要求の分類

- 機能: 製品が何を行うか
- 性能: どの条件で、どの範囲・精度・速度を満たすか
- インターフェース: 機械、電気、熱、情報、人との境界
- 環境: 温度、湿度、振動、汚染、屋内外など
- 安全・法規・規格: 適用範囲と版を含む
- 製造・組立・検査: 工法、基準、アクセス、受入方法
- 保守・寿命: 交換、清掃、校正、耐久、保管
- 成果物: CAD、回路図、BOM、レポート、試験記録など

要求と設計選択を分ける。

```text
要求: 製品は指定した荷重条件で永久変形しないこと。
設計選択: 材料をA5052とし、板厚を2 mmとする。
```

材料や部品型番を固定する理由がなければ、要求ではなく候補または制約として扱う。

## 3. 要求文とトレーサビリティ

各要求を1行1義務にし、安定したIDを付ける。

```markdown
| ID | 要求 | 条件・範囲 | 根拠/出典 | 検証 | 合格基準 |
|---|---|---|---|---|---|
| MECH-ENV-001 | 筐体は内部部品を保持すること | 指定姿勢、指定荷重 | ユーザー要望 | Test | 試験後に脱落・破損なし |
```

良い要求に含める要素:

- 対象と動作
- 適用条件
- min/nominal/maxまたは公差
- 単位
- 例外
- 検証可能な合格基準

避ける表現:

- 「適切な」「十分な」「可能な限り」「高性能」
- 根拠のない「標準」「一般的」「規格準拠」
- 1文中の複数要求
- 設計方法を不要に固定する表現
- 条件のない単一代表値

NASA Systems Engineering Handbookは、要求を一つの `shall` を持つ完全な文として書き、根拠を保持し、固有ID・成功基準・検証方法を要求検証マトリクスに結ぶ考え方を示している。本スキルでは日本語でも同じ構造を採用する。

## 4. インターフェース

境界ごとに次を記録する。

| 項目 | 内容 |
|---|---|
| Interface ID | 例: IF-PCB-ENC-001 |
| owner A / B | 寸法・信号・変更を管理する側 |
| source revision | 図面、データシート、CAD、仕様の版 |
| coordinate frame | 原点、軸、面、単位、正方向 |
| nominal geometry | 寸法、位置、ピン、ネット、流量など |
| tolerance / limit | 双方の許容差と必要マージン |
| dynamic envelope | 挿抜、可動、工具、ケーブル、熱膨張 |
| verification | inspection / analysis / demonstration / test |
| evidence | レポート、測定、モデル、ログ |

「位置が一致」だけでは不十分である。どの原点から、どの方向に、どの公差で一致するかを書く。

## 5. TBD・TBR・仮定

- TBD: 値または内容が未決定
- TBR: 暫定値はあるが確認が必要
- Assumption: 設計を進めるために置いた仮定

```markdown
| ID | 種別 | 内容 | 影響 | owner | 解消方法 | 期限/マイルストーン |
|---|---|---|---|---|---|---|
| TBR-001 | TBR | PCB厚を1.6 mmと仮置き | ボス高とコネクタZ位置 | EE | 基板製造仕様を確認 | CAD release前 |
```

仮定を満たさない場合に影響する要求・部品・成果物を追跡する。

## 6. 検証計画

| 方法 | 用途 | 証拠の例 |
|---|---|---|
| Inspection | 図面、BOM、外観、属性の確認 | チェック済み図面、BOM diff |
| Analysis | 計算、CAD、SPICE、許容差解析 | 計算書、JSON、シミュレーション結果 |
| Demonstration | 定性的な機能確認 | 操作記録、動画、写真 |
| Test | 規定条件での定量試験 | 手順、校正情報、生データ、判定 |

各検証行には、要求ID、条件、合格基準、設備/モデル、担当、時期、証拠、結果を含める。解析やシミュレーションは、使用モデルと仮定の範囲だけを立証する。

## 7. テンプレートの選び方

- `templates/spec/mechanical-spec.md`: 単体部品、筐体、治具、機構
- `templates/spec/circuit-spec.md`: 回路、電源、信号処理、インターフェース
- `templates/spec/integrated-spec.md`: PCB、筐体、コネクタ、熱、組立の結合設計

テンプレートに不要な節は削除してよいが、要求ID、仮定/TBD/TBR、検証マトリクス、出典は残す。

## 8. レビュー基準

- 上位要望から要求への抜けがない
- 互いに矛盾する要求がない
- 単位、座標、データム、方向が一貫している
- 公差とマージンが製造・測定能力に対応している
- 規格番号、版、状態、適用範囲が確認されている
- 部品固有値は採用型番の一次資料に結び付く
- 合否判定を実行できる
- 未解決項目の責任者と解消条件がある
